A native S3 client for macOS and Windows, in Rust and GPUI. First build offered
to anyone outside the machine it was written on.

## Why this one is worth trying

**S3 Express One Zone directory buckets are first-class, including buckets in
an AWS Local Zone.** That is the part almost nothing else does, and the reason
is that directory buckets are not general purpose buckets with a different
name:

- `ListBuckets` **does not return them at all**, so an account holding only
  directory buckets looks *empty* in most clients.
- They authorize through `s3express:CreateSession`, not the object permission
  a refusal superficially resembles — so most tools name the wrong fix.
- Their namespace is real and hierarchical: a folder exists only while
  something is in it.
- Their zone id may be an Availability Zone (`usw2-az1`) or a **Local Zone**
  (`apse1-han1-az1`).

caixonho lists them beside general purpose buckets, says which listing was
refused when only one was, names `s3express:CreateSession` when that is the
permission you lack, and refuses to create an empty folder there — saying why,
and what does work instead — rather than writing a marker the service deletes a
moment later.

Developed against **Local Zone** directory buckets in `apse1-han1-az1` (Hanoi):
listed, browsed, uploaded to, downloaded from, previewed and deleted in on real
ones, not inferred from documentation.

## What else is in it

- Connects through `~/.aws` profiles — SSO with a cached token,
  `credential_process`, static keys — or a credential you type in, whose secret
  goes to the system keychain and nowhere else.
- Says which buckets your credentials can actually open, and names the IAM
  action a refused one needs. A bucket nobody has asked about yet says so
  rather than guessing.
- Follows a wrong-region redirect to where a bucket actually lives instead of
  handing back the error.
- Browses prefixes as folders, a page at a time, with a path you can type into.
- **Transfers**: drag files onto the window or pick several at once; up to four
  run together and the rest queue, each with its own progress, outcome and
  collision question. One failure does not stop the others. Cancel one, cancel
  all, retry failed, clear finished.
- **Never replaces an object without asking**, and the promise is made by S3
  itself (`If-None-Match`) rather than by a check this app hopes to win.
- **Deletes only after a confirmation naming the exact key**, and offers Undo
  exactly when the service's own response proves a delete marker exists.
- **Previews** text and small images without downloading them, saying honestly
  how much of the whole you are looking at.
- Narrows a long bucket list by region, kind, name and whether you can open it
  — and remembers which buckets a connection shows.

## What is not in it

Stated plainly, because a beta that oversells is worse than one that is small.

- **No installer.** macOS is an `.app` you drag to Applications; Windows is a
  portable `.exe`. Neither writes to a system location or registers an
  uninstaller.
- **No code signing or notarization.** See below.
- **Signing in to IAM Identity Center from the app is built but unproven.** The
  button is there and refuses to appear where it could not work, but nobody has
  completed a sign-in with it on a real account yet. Until that is verified,
  treat the AWS CLI as still required for SSO.
- **No pause or resume** on transfers. A `PutObject` is one stream and stopping
  it is cancelling it; honest pausing needs multipart, which is not built.
- **No throughput or ETA**, no multipart, no adaptive retry on throttling.
- **No folder upload** and **no recursive or bulk delete** — a dropped folder is
  refused with a reason rather than half-uploaded, and `Delete…` acts on one
  object.
- **Files above 5 GiB are refused up front**, for the same missing multipart.
- **No sorting**, and no server-side prefix search.
- **Undo after a delete has only been exercised on buckets that keep no
  versions**, where it correctly does not appear. The restoring path itself is
  covered by tests and has not been watched on a versioned bucket.
- **macOS builds are Apple Silicon only.** No Intel binary and no universal
  one; CI builds a single architecture.
- **Not measured at 100k objects** on a real listing. The claim in the README's
  header comes from a synthetic benchmark, and is marked as such.

## The warning you will see, and what it means

These builds are **not signed and not notarized**.

- **macOS**: *"Apple could not verify caixonho-gui is free of malware."* That
  means unverified, not malicious. **System Settings → Privacy & Security →
  Open Anyway.**
- **Windows**: SmartScreen's *"Windows protected your PC"* → **More info → Run
  anyway**.

Both are doing their job. caixonho reads AWS credentials, so clicking through
them is a decision rather than a formality — do it only for a build you fetched
yourself from this repository's own CI, and not because someone sent you a file.

Signed and notarized builds are milestone M4.

## Reporting something

Logs are local and carry no telemetry: `~/Library/Logs/caixonho` on macOS,
`%LOCALAPPDATA%\caixonho\logs` on Windows. They record bucket and connection
names, so read one before attaching it to anything public.
