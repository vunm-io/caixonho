# caixonho v0.1.0-beta.4

The first build that looks like itself, and the first that can tell you what it
is.

## What is new

**Đất Nặn, the owner's own design system, in the window.** A single light
palette, and two families embedded with their licences — Baloo 2 for display
and Be Vietnam Pro for everything read at length. Pressed things get their
clay; cards stop leaking; hover is stated rather than derived.

**Partly, and the notes say which part.** `XONHO-0032` is not finished and this
does not pretend otherwise: the palette, the fonts, the light theme and the
pressed-state treatment are in. The sidebar's current item, the flattening of
everything that is not a surface, and a selected row are **not** — they still
wear the old treatment. The window is deliberately mixed, and that is what you
are looking at rather than a half-broken one.

**The window says which build it is.** Bottom right, beside the log directory:
the version and the commit it was built from. Two facts in one line, because
they answer the same person at the same moment — *what is this, and where is
its log.* The commit is there because between releases the version is the last
one tagged, and only the commit tells two such builds apart.

**The files say which release they are.** `caixonho-0.1.0-beta.4-macos-arm64.zip`
and `caixonho-0.1.0-beta.4-windows-x86_64.exe`. Three files called
`caixonho-macos-arm64.zip`, `(1)` and `(2)` sat in one Downloads folder on
2026-09-05 and only a checksum said which release each was.

Underneath: one declared version now feeds the window, the macOS bundle's
metadata and those file names. It had been three numbers with no source —
`0.0.0` in the manifest, a hardcoded `0.1.0` in the bundle, and whatever the
newest tag said.

## What is measured and not good enough

The theme's contrast was measured against WCAG AA rather than eyeballed, and it
is reported here rather than quietly shipped.

Text you read is comfortable: body text is **8.51** on the app surface, 8.02 in
the sidebar, 9.41 in a popover, and secondary text 4.87 — all above the 4.5 AA
asks for. Six pairs are below it:

- **`link.hover` is 2.78**, which fails even the 3.0 allowed for large text.
  Hover is the moment before a click, and it is the worst pair in the theme.
- A link at rest is 3.71, and the danger and success button labels are 3.71 and
  3.83 — legible large, under the bar for the normal-size text a button label
  is.

These are the design system's own values, so changing them is a decision rather
than a fix, and it has not been made yet. If you find the orange hover hard to
read, you are not imagining it.

## What is not in it

Everything `v0.1.0-beta.2`'s notes list is still absent, and these are the parts
this release touches or adds to.

- **The rest of Đất Nặn**, named above.
- **No dark theme**, deliberately: the design system defines one light palette,
  and inventing a dark one here would be this application inventing brand.
- Still no installer, **no Developer ID signature and no notarization**, no
  pause or resume, no throughput or ETA, no multipart — files above 5 GiB are
  refused up front — no folder upload, no sorting, no server-side prefix
  search, and no Undo after a bulk delete.
- **Signing in to IAM Identity Center from the app is still unproven.** Treat
  the AWS CLI as required for SSO.
- **macOS builds are Apple Silicon only.**

## The files

| File | For | What to do with it |
|---|---|---|
| `caixonho-0.1.0-beta.4-macos-arm64.zip` | macOS on **Apple Silicon** — an Intel Mac will not run it | Unzip, drag **Caixonho.app** to Applications |
| `caixonho-0.1.0-beta.4-windows-x86_64.exe` | Windows on x86-64 | Run it. Portable — nothing is installed |

Because nothing here is signed by an identity, the checksums are the only way
to tell that what you downloaded is what CI built:

```
MACOS_SHA  caixonho-0.1.0-beta.4-macos-arm64.zip
WIN_SHA  caixonho-0.1.0-beta.4-windows-x86_64.exe
```

Both built from `BUILD_COMMIT`, [run BUILD_RUN](https://github.com/vunm-io/caixonho/actions/runs/BUILD_RUN).

Newer builds appear as **Artifacts** on every green
[Actions run](https://github.com/vunm-io/caixonho/actions), though those need a
GitHub account — artifacts are not served anonymously even from a public
repository, while the files attached here are.

## The warning you will see, and what it means

These builds are **not signed by a developer identity and not notarized**.

- **macOS**: the first open is refused, and on current macOS the dialog says
  *"Caixonho" is damaged and can't be opened* — that is Gatekeeper's wording
  for **untrusted**, not for a broken file. The bundle verifies; the system log
  records the refusal as *"Code did not match any currently allowed policy"*.
  Click **Cancel**, not Move to Trash. That attempt registers the block. Then
  open **System Settings → Privacy & Security**, scroll to the bottom of the
  *Security* section to *"Caixonho" was blocked to protect your Mac*, and click
  **Open Anyway**; confirm once more. The offer stands for about an hour after
  the attempt, so do it straight away.
- **Windows**: SmartScreen's *"Windows protected your PC"* → **More info → Run
  anyway**.

Both are doing their job. caixonho reads AWS credentials, so clicking through
them is a decision rather than a formality — do it only for a build you fetched
yourself from this repository's own release page, and not because someone sent
you a file.

If you would rather not click through, removing the download's quarantine mark
makes Gatekeeper skip the app entirely. Only for a copy you fetched yourself:

```
xattr -d com.apple.quarantine /Applications/Caixonho.app
```

## Reporting something

**Quote the line in the bottom-right of the window.** It names the version and
the commit, and this is the first release where a report can carry it.

Logs are local and carry no telemetry: `~/Library/Logs/caixonho` on macOS,
`%LOCALAPPDATA%\caixonho\logs` on Windows. They record bucket and connection
names, so read one before attaching it to anything public.
