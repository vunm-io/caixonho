# Design — Đất Nặn, in a desktop window

## Context

The system was read before anything was decided, along the route its own
`SKILL.md` prescribes: `readme.md` for the two tiers and the voice,
`REPO-NOTES.md` for what is deliberately missing, then the one UI kit that
applies — `ui_kits/desktop/`.

It lives at
`vunm-skills/plugins/vunm-skills/skills/dat-nan-design/`, and the same tokens
are copied into `vunm-site/docs/design/handoff-vsite-0001/css/`. The skill is
the source; the site's copy is a handoff.

What the toolkit can do was checked the same way, by reading gpui rather than
assuming:

| Signature | gpui |
|---|---|
| Two-layer inset shadow — *"DNA của chất đất nặn"* | `BoxShadow { inset: bool }`, `paint_inset_shadows` — **yes** |
| Warm drop shadows | yes |
| Asymmetric per-corner radii | `Corners { top_left, top_right, … }` — yes, in pixels |
| Elliptical blob radii | corners are `Pixels`, not percentages — **no** |
| Tilt, and the squish on press | no transform on a div — **no** |
| Embedded fonts | `text_system().add_fonts()` — yes |

## Goals / Non-Goals

**Goals**

- Every colour, size, radius and space in the window traceable to a token the
  system names.
- Clay exactly where the desktop kit puts it, and nowhere else.
- Both fonts embedded, so the binary stays self-contained.
- The two lost signatures written into `docs/design-language.md`.

**Non-Goals**

- Blob radii and the squish. Named above; not imitated.
- A dark theme. The system has none and the owner chose to drop ours rather
  than invent one.
- Re-laying-out the window. This change dresses what is there. The desktop kit
  has a 300px detail panel caixonho does not have, and adding one is a feature,
  not a repaint.

## Decisions

### The app branch, not the web one

`--surface-app` `#F2F4F0` for the pane, `--surface-app-sidebar` `#EAEEE7` for
the sidebar, `--surface-app-raised` `#FFFFFF` for the header and for a
selected row, `--app-line` for every rule.

This is the system's instruction and it comes with its reason: *"trong app,
mảng nền lớn màu vàng làm dữ liệu khó đọc và trông cũ"*. Taking the warm paper
because it is more recognisably the brand would be choosing the logo over the
reader.

### Clay is a short list, and the list is the kit's

From `ui_kits/desktop/README.md`: *"Clay trong app này chỉ còn ở sidebar (mục
đang xem), nút, chip và badge."*

So: the sidebar's current bucket, the buttons in the path bar and in every
strip, the status badges. Nothing else — and in particular **not** the object
table, not the bucket table, and not the strips' own surfaces.

A selected row is *"nền giấy sáng + viền xanh ngọc mảnh"* — `--clay-aqua`,
1.5px — and explicitly **not** a yellow fill and **not** lifted. That matters
here more than on the web: this application shows rows a user may act
destructively on, and a selection that shouts is a selection that gets
confirmed without being read.

### Delete stays terracotta

The owner asked whether the destructive verb should keep its current red, and
the answer came from the system rather than from taste: the desktop kit's own
delete is `IconButton tone="danger"`, and `--status-danger` is
`--clay-terracotta` `#D4552F`.

It is warmer than what is there now. It is also the only colour of its kind on
the screen — nothing else in the app palette is red-orange — so it separates by
being unique rather than by being loud. `XONHO-0030`'s counted confirmation is
the guard that lets that be enough.

### Baloo 2 is variable, and that is a risk to test rather than reason about

`google/fonts` ships Baloo 2 as one variable file, `Baloo2[wght].ttf`. gpui
picks a weight through font-kit's properties, and whether that reaches a
variable font's `wght` axis is not obvious from the source.

So it gets **tested**, with the screenshot harness that already exists: render
a frame with a label at 400 and a title at 800 and look at whether they differ.
If they do not, the fallback is static instances of the same family, which is a
download and not a redesign.

Be Vietnam Pro ships static, so three files — regular, semibold, bold — and no
question.

### One theme, and the dark one goes

Not "kept and left stale". `theme.json` loses its dark entry, and the mode
follows. A dark theme built from values the system never specified would be
this project inventing brand, which `REPO-NOTES.md` forbids in as many words.

## Risks / Trade-offs

- **[The brand loses its motion signature]** → and the system says that
  signature is the brand. This is the largest cost, it is unavoidable on this
  toolkit, and the mitigation is to say so rather than to fake it.
- **[Every screenshot frame changes]** → all thirty-nine. They are judgement
  frames, regenerated by one command, and they have to be **looked at** rather
  than merely regenerated: this change alters every one of them, so a rendering
  defect has thirty-nine places to hide.
- **[Contrast]** → the system pairs each clay colour with its own ink for a
  reason, and warns that a diluted background needs a darker ink than the pure
  colour. Every pair used here has to be the one the system names; picking a
  neighbour because it looks better is how a label becomes unreadable at 13px.
- **[Losing dark mode is a regression for whoever used it]** → the owner chose
  it knowingly, and the way back is through the design system rather than
  through this repository.

## Open Questions

- **The detail panel.** The desktop kit has a 300px right-hand panel showing
  the selected file, its metadata and its actions. caixonho has a preview
  surface but no panel, and `XONHO-0030` moved the row's verbs into a context
  menu. Whether that panel is the better home for them is a real question —
  and a feature, so not this change.
